# Abyssal Rebuild Generator

`generate_abyssal_sites.py` is the deterministic source of truth for the six deep abyssal structure NBTs.

Run from repository root:

```bash
python tools/abyssal_rebuild/generate_abyssal_sites.py kubejs/data/infinite_domain/structure/abyssal --verify
```

The generator embeds the authoritative expected Git blob hashes and fails verification if any generated byte differs. The GitHub materialization workflow calls the same verification path before it is permitted to commit NBTs, so there is no second hash list to keep synchronized.

The generated templates use Minecraft 1.21.1 `DataVersion 3955`, deterministic gzip (`mtime=0`), the existing stable structure filenames, site-specific evidence loot tables, and secondary salvage tables.

## Accessibility contract

Each generated deep installation contains an intentional 3 × 3 underwater breach through its outer shell. Omitted structure-template blocks leave the surrounding water in place, providing a swim-through entrance without requiring the player to mine the structure. The Karsic hadal blacksite additionally has a second 3 × 3 opening through its inner archive vault and a matching opening through the iron-bar vestibule.

These are deliberately flooded/open-breach mechanical interiors. They are not claimed to be dry pressure habitats. Heavy Rebuild work may later create damaged pressure compartments or airlocked sections, but it must preserve chest accessibility, stable structure IDs, evidence contracts, and the ability to complete the expedition without destructive mining.

## Current evidence contract

Each generated site contains:

- one guaranteed site-specific evidence chest;
- one secondary generic abyssal or hadal salvage chest.

The active FTB quest chapter requires the player to enter the matching structure and possess the evidence item recovered from that chest. Deep evidence is not issued by quest completion.

Runtime placement, flooding appearance, submarine approach clearance, and chest interaction remain deferred observations under the explicit 2026-08-22 runtime-validation waiver.
