# 04A — Structure Revision Matrix Guide

`04_STRUCTURE_REVISION_MATRIX.csv` contains 64 target locations. The `preferred_audited_source_archetype` column is deliberately generic because the exact post-review schematic names are repository facts Codex must discover.

## Mapping procedure

For each target:

1. Filter the reviewed structure catalog by approximate function and footprint.
2. Prefer `keep-with-fixes` or `strong revision source` assets over rejected assets.
3. Open the candidate and verify that its circulation and scale can be transformed without creating a structurally absurd facility.
4. Record the mapping before editing.
5. Create the narrative revision under a stable new ID.
6. Apply design-language modules, damage phase, proof item, deterministic critical lore, ambient loot, and locator metadata as required.
7. Validate in-world.

## If several rows reuse one source shell

That is allowed only if the resulting variants are genuinely differentiated. Avoid a world where six corporations all occupy the same building with different signs.

When reusing a shell more than once, force stronger differentiation in:

- entrance placement;
- vertical circulation;
- room zoning;
- exterior annexes/tanks/loading bays;
- internal machinery;
- damage pattern;
- palette and signage;
- surrounding site furniture;
- loot/evidence route.

## If the matrix conflicts with the audit catalog

The narrative function is more important than preserving a bad source mapping. Use a different audited structure or a new modular build. Do not distort a tiny storefront into a nuclear command center simply to satisfy a reuse percentage.

## Minimum reuse goal

Aim to derive **at least 75%** of the 64 variants from the reviewed structure inventory or modules extracted from it. This is a production-efficiency goal, not a canon rule. If the reviewed inventory lacks the needed industrial/scientific archetypes, build the missing ones and document the gap.

## Generic structures versus quest variants

Keep generic structures available for ordinary city density. Quest variants should be registered separately so a narrative location can have:

- deterministic proof loot;
- specialized locator support;
- controlled rarity;
- more expensive detail;
- unique environmental evidence;
- optional or mandatory quest targeting.

Do not globally replace every warehouse with Pleroma, every lab with VCF, or every office with Blackglass. Repetition should build recognition, not erase variety.
