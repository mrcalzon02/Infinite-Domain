# Overworld biome-modifier attachment

## The bug class

A mod that injects worldgen with a NeoForge biome modifier gated on
`#minecraft:is_overworld` **generates nothing in this pack** until its biomes are
named explicitly.

Vanilla's `minecraft:is_overworld` biome tag enumerates vanilla biomes. It is not
a dimension predicate and nothing adds to it automatically. Across the 193 mod
jars in this instance, exactly one (Quark, for `quark:glimmering_weald`) adds a
biome to it; EnviroMine Lite ships an empty additive copy.

The Infinite Domain overworld is generated by an `isekai_api:climate_zones` biome
source whose **fallback is `wastelands:apocalypse`** — that is, the default
biome for the bulk of the world is modded. Of the 63 biomes the live preset can
place, 23 are modded and none of them are in `#minecraft:is_overworld`.

So any `#minecraft:is_overworld`-gated feature only ever appeared in the narrow
vanilla climate bands the preset still routes to (beaches, oceans, some
temperate/badlands/jungle bands, `deep_dark`), and never in the wasteland that
players actually cross.

This has now bitten twice:

| Mod | Feature | Symptom | Fix |
| --- | --- | --- | --- |
| EnviroMine Lite | `hot_coal_ore` / `deepslate_hot_coal_ore` | the whole gas-pocket / `toxic_air` layer was inert | `#infinite_domain:has_enviromine_gas_pockets` (see `ENVIRONMENTAL_SURVIVAL_ENGINEERING.md`) |
| Lost Cities | `lostcities:lostcities` | **no city generated anywhere in the overworld, ever** | `#infinite_domain:lostcities_city_biomes` |

## Lost Cities, specifically

Lost Cities' own attachment is, in `lostcities-1.21-8.4.1.jar`:

```json
// data/lostcities/neoforge/biome_modifier/lostcities.json
{ "type": "neoforge:add_features", "biomes": "#minecraft:is_overworld",
  "features": "lostcities:lostcities", "step": "raw_generation" }
```

Everything downstream of that hook was already built and correct:

- `config/lostcities-server.toml` → `selectedProfile = "infinite_domain"`.
  Confirmed against `Config.getProfileForDimension`: for `Level.OVERWORLD`, when
  the per-world `LostData` profile is empty the mod falls back to exactly this
  config value. (`[profiles].dimensionsWithProfiles` is for *other* dimensions
  and correctly does not mention the overworld.)
- `config/lostcities/profiles/infinite_domain.json` — city density identical to
  the stock `default`/`wasteland` profiles (`cityChance 0.01`, `cityThreshold
  0.2`, `cityPerlinScale 3.0`), with `citySpawnMultiplier1/2` left at `1.0` so
  there is **no** spawn-radius suppression.
- `kubejs/data/lostcities/lostcities/worldstyles/standard.json` — city-biome
  multipliers, per-region city styles, Infinite Domain highway/railway parts and
  a scattered-structure table.
- `mods/infinite-domain-lostcities-highway-compat-1.0.0.jar` — keeps the
  intercity highway planner from bridging ocean/abyssal terrain.

None of it ran, because the feature was never in any generated biome's feature
list.

### The fix

```
kubejs/data/infinite_domain/tags/worldgen/biome/lostcities_city_biomes.json
kubejs/data/infinite_domain/neoforge/biome_modifier/lostcities_cities.json
```

The modifier mirrors Lost Cities' own one exactly (`neoforge:add_features`,
`lostcities:lostcities`, step `raw_generation`) but targets
`#infinite_domain:lostcities_city_biomes`.

The tag lists **only** the 14 modded *land* biomes. Vanilla biomes are
deliberately omitted: they are already covered by Lost Cities' own modifier, and
adding the same feature twice to one biome would run the city generator twice per
chunk.

Included (14): the five `wastelands:*` land biomes, the three
`the_wasteland_reworked:*` land biomes, `infinite_domain:polluted_shore`, and the
five `infinite_domain:karsic_*` biomes.

`wastelands:mountains` is included even though the worldstyle gives it a city
multiplier of `0.0` via `#infinite_domain:wasteland_mountain_military_biomes`.
The feature has to run in a chunk for **anything** to be placed there, including
highway segments and the `mountain_pass_terminator` scattered building, which is
declared `nearhighway: true`.

Deliberately excluded, enumerated with reasons in
`dev/scripts/audit_lostcities_biome_attachment.py`:

- `infinite_domain:safe_zone` — the protected ~128-block-diameter spawn disc. A
  city here would overwrite the start area. This does not stop cities *near*
  spawn: the disc is small and no spawn-distance suppression is configured, so
  ordinary city placement resumes immediately outside it.
- the eight `infinite_domain:*` slope / abyssal-plain / fracture-field /
  hadal-trench seafloor biomes — already zeroed by
  `#infinite_domain:lostcities_city_excluded`, and running the feature there
  would only burn generation time.

### Guard

`dev/scripts/audit_lostcities_biome_attachment.py` fails when a modded overworld
biome in either world preset is in neither the tag nor the exclusion list, and
specifically calls out the biome-source **fallback** not being attached. Run it
whenever a biome is added to a preset.

### A second Lost Cities bug found alongside this

All six of Lost Cities' own block tags (`foliage`, `rotatable`, `easybreakable`,
`notbreakable`, `lights`, `needspoi`) were also loading empty, because the jar
ships them at the pre-1.21 `tags/blocks` path. They drive foliage avoidance, ruin
breakability, scattered-building rotation and POI handling. Ported to
`kubejs/data/lostcities/tags/block/*.json` — see `LEGACY_TAG_PATHS.md`.

Nobody could have noticed those before, because no city had ever generated.

## Runtime evidence (2026-09-08)

The attachment was confirmed in a live isolated NeoForge runtime, not inferred. A
temporary KubeJS probe walked each biome's `getGenerationSettings().features()`
looking for the `lostcities:lostcities` placed feature, during a fixed-seed smoke
benchmark (`dev/scripts/run_worldgen_benchmark.ps1 -Variant baseline -Suite smoke`):

```
LCPROBE wastelands:apocalypse             lostcities=true    <- the fallback biome, bulk of the world
LCPROBE wastelands:city                   lostcities=true
LCPROBE wastelands:mountains              lostcities=true
LCPROBE infinite_domain:karsic_district   lostcities=true
LCPROBE infinite_domain:polluted_shore    lostcities=true
LCPROBE minecraft:plains                  lostcities=true    <- Lost Cities' own modifier, unchanged
LCPROBE infinite_domain:safe_zone         lostcities=false   <- deliberately excluded
LCPROBE infinite_domain:western_abyssal_plain lostcities=false <- deliberately excluded
```

Every value matched the intent. The run completed 16 chunks with **zero
ERROR/FATAL lines** and no probe errors, so the newly active feature does not
throw during generation. The probe script was removed afterwards; re-create it
from this listing if the attachment ever needs re-checking.

Before the fix, every one of those modded biomes would have reported `false`.

## Scope note

Only new chunks are affected. Already-generated chunks in existing saves keep the
terrain they have; cities appear as the player travels into fresh chunks, or in a
new world.

Headless load is not visual acceptance. `dev/docs/worldgen-benchmark/README.md`
is explicit that `acceptance.lostCities.runtimeLoadAccepted` proves only that the
mod loaded during a successful fixed-seed generation — it says nothing about
skyline quality, terrain seating, frequency or distribution. Lost Cities also
generates as a *feature*, not a structure, so it never appears in
`structureStartsByNamespace`; a city cannot be confirmed from structure-start
instrumentation. In-world review is still owed.
